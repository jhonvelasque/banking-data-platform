# 4. De Cloud SQL a GCS y Procesamiento de la Capa Bronze (Cloud SQL to GCS and Bronze Processing)

Esta sección cubre el diseño y la implementación de las canalizaciones de datos (pipelines) para la ingesta incremental de datos operacionales (*batch*) desde **Cloud SQL** hacia la capa de aterrizaje (**GCS**) y su posterior procesamiento hacia las tablas **Bronze** de nuestro almacén analítico (**BigQuery**).

---

## Estructura de Componentes en el Proyecto

*   **Pipeline de Ingestión CDC (Dataflow / Apache Beam):** [cloudsql_cdc_pipeline.py](../airflow/data/dataflow/cloudsql_cdc_pipeline.py)
*   **Pipeline de Carga Bronze (Dataproc / Apache Spark):** [bronze_gcs_to_bq.py](../airflow/data/dataproc/bronze_gcs_to_bq.py)

---

## 1. Ingestión CDC con Cloud Dataflow (Apache Beam)

Para extraer las modificaciones incrementales de la base de datos MySQL sin sobrecargarla, implementamos un pipeline en **Apache Beam** que corre sobre **Cloud Dataflow**.

### Lógica del Pipeline:
1.  **Lectura incremental:** El pipeline lee de la tabla de metadatos de BigQuery (`banking_metadata.cdc_config`) para conocer el `last_success_ts` (marca de tiempo del último procesamiento exitoso) de cada tabla (`customers`, `accounts`, `transactions`).
2.  **Consulta filtrada:** Ejecuta una consulta sobre Cloud SQL MySQL filtrando los registros cuya columna de marca de agua (`updated_at`) sea superior al timestamp de metadatos.
3.  **Formato Parquet:** Convierte los registros extraídos a formato **Parquet** (un formato columnar altamente comprimido y optimizado para analítica).
4.  **Escritura en GCS:** Guarda los archivos Parquet en las carpetas correspondientes dentro de nuestro bucket de aterrizaje:
    *   `gs://banking-raw-dev-<ID>/customers/`
    *   `gs://banking-raw-dev-<ID>/accounts/`
    *   `gs://banking-raw-dev-<ID>/transactions/`

---

## 2. Carga a la Capa Bronze con Cloud Dataproc (Apache Spark)

Una vez que los archivos Parquet están almacenados en GCS, utilizamos un trabajo de **Apache Spark** ejecutándose en **Cloud Dataproc** para procesar y cargar los datos crudos en BigQuery.

### Lógica de Carga a BigQuery:
1.  **Lectura de GCS:** Lee los nuevos archivos Parquet acumulados en las carpetas de GCS.
2.  **Carga a Bronze:** Inserta los datos directamente en las tablas correspondientes del dataset `banking_bronze`:
    *   `banking_bronze.bronze_customers`
    *   `banking_bronze.bronze_accounts`
    *   `banking_bronze.bronze_transactions`
3.  **Inyección de Auditoría (Watermark):** Agrega una columna técnica `bronze_load_ts` con la marca de tiempo de la carga actual para mantener la trazabilidad de los datos.
4.  **Registro de Metadatos de Auditoría:** Escribe una entrada en `banking_metadata.ingestion_audit_log` registrando:
    *   El total de filas procesadas.
    *   El estado final de la ejecución (éxito o error).
    *   La marca de tiempo de inicio y fin.
5.  **Actualización de Watermark:** Actualiza el valor de `last_success_ts` en `banking_metadata.cdc_config` para que la próxima ejecución batch comience a partir de este punto en el tiempo.
