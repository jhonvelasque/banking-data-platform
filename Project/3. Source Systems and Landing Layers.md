## 6. Configuración del Origen 1 - Instancia de MySQL en Cloud SQL (Set Up Source 1 - Cloud SQL MySQL Instance)

Esta sección explica de manera detallada y paso a paso cómo crear y configurar la base de datos operacional **Cloud SQL** utilizando el motor **MySQL** en Google Cloud Platform (GCP). Esta guía está diseñada para que cualquier persona, incluso sin conocimientos previos de GCP o bases de datos, pueda seguirla con facilidad.

---

### Paso 1: Acceso a Cloud SQL en la Consola de GCP

1.  Abre tu navegador de internet e ingresa a la consola de Google Cloud: [console.cloud.google.com](https://console.cloud.google.com).
2.  Inicia sesión con tu cuenta de GCP.
3.  En la barra superior de la consola, asegúrate de tener seleccionado el proyecto del curso: **`Dev Banking 2026`** (o el nombre que le diste a tu proyecto).
4.  En la barra de búsqueda superior, escribe **`Cloud SQL`** y haz clic en el primer resultado con el ícono de base de datos.
5.  Se abrirá el panel principal de Cloud SQL. Si es la primera vez que entras, verás una pantalla de bienvenida.

---

### Paso 2: Creación de la Instancia de Base de Datos MySQL

1.  Haz clic en el botón **`Create Instance`** (Crear instancia) ubicado en la barra de herramientas superior.
2.  **Selección del Motor:** En la ventana de selección de motor de base de datos, haz clic en el botón **`Choose MySQL`** (Elegir MySQL).
3.  **Configuración de la Edición de la Instancia:**
    *   Selecciona **`Cloud SQL Enterprise Edition`** (Edición adecuada para cargas de trabajo estándar y desarrollo).
    *   En la sección de plantillas de entorno (Preset), selecciona **`Development`** (Desarrollo / Sandbox). Esto optimiza los recursos para pruebas y reduce los costos del laboratorio.
4.  **Información de la Instancia:**
    *   **Instance ID (ID de la instancia):** Escribe un nombre identificativo en minúsculas y separado por guiones, por ejemplo: **`banking-db-mysql`**.
    *   **Root Password (Contraseña del administrador):** Genera o introduce una contraseña segura (por ejemplo: `mypass@123`). **¡Importante!** Anota y guarda esta contraseña, ya que es la llave de administración principal de tu base de datos.
    *   **Database Version (Versión de base de datos):** Selecciona **`MySQL 8.4`** (LTS) o la versión estable más reciente disponible.
5.  **Ubicación (Region y Zone):**
    *   **Region (Región):** Selecciona **`us-central1 (Iowa)`** (o la región más cercana a ti).
    *   **Zonal availability (Disponibilidad de zona):** Selecciona **`Single zone`** (Zona única). Esta opción es ideal para entornos de desarrollo y evita duplicar el costo mensual (el costo estimado será de aproximadamente $0.30 USD por hora).
6.  **Configuración de Hardware (Machine Configuration y Storage):**
    *   Haz clic en **`Customize Instance`** (Personalizar instancia) para ajustar el tamaño de la máquina si es necesario:
        *   **Machine type (Tipo de máquina):** Elige una máquina ligera, **`2 vCPU, 8 GB de RAM`** (Shared core / Núcleo compartido o estándar) es más que suficiente para este proyecto.
        *   **Storage (Almacenamiento):** Selecciona tipo **`SSD`** con una capacidad de **`20 GB`**.
7.  **Conexiones de Red (Connections):**
    *   Asegúrate de que la opción **`Public IP`** (IP pública) esté habilitada.
    *   En la sección de redes autorizadas, haz clic en **`Add Network`** (Agregar red).
        *   **Nombre:** `Permitir Acceso`
        *   **Network (Red):** Escribe `0.0.0.0/0` (esto permite conectarse desde cualquier dirección IP de forma externa durante tu desarrollo, solo recomendado para laboratorios de práctica).
8.  **Protección de Datos y Eliminación:**
    *   Desplázate hacia abajo hasta la sección **`Data Protection`** (Protección de datos).
    *   **¡Muy Importante!** Desmarca la casilla **`Enable deletion protection`** (Habilitar prevención de eliminación). Si dejas esta opción activada, GCP no te permitirá borrar la base de datos cuando termines tu práctica, lo cual podría generarte cargos innecesarios en tu tarjeta de crédito al finalizar el laboratorio.
9.  **Crear Instancia:**
    *   Revisa el resumen de configuración a la derecha y haz clic en **`Create Instance`** (Crear instancia).
    *   *Nota:* La creación física de la máquina y la instalación de MySQL tardará entre 2 y 5 minutos. Verás un círculo de carga junto al nombre de la instancia en el panel de Cloud SQL. Espera a que cambie a un ícono de verificación verde.

---

### Paso 3: Creación de un Usuario para Desarrollo (Remote User)

Por motivos de seguridad, nunca es recomendable conectarse a una base de datos utilizando el usuario principal `root`. Crearemos un usuario exclusivo para el desarrollo:

1.  En la barra lateral izquierda dentro de tu instancia de Cloud SQL, haz clic en la sección **`Users`** (Usuarios).
2.  Haz clic en el botón **`Add User Account`** (Agregar cuenta de usuario).
3.  Ingresa los siguientes datos en el formulario:
    *   **User name (Nombre de usuario):** **`myuser`**
    *   **Password (Contraseña):** Introduce una contraseña de desarrollo (por ejemplo: `mypass@123`).
    *   **Host name:** Selecciona **`Allow any host`** (Permitir cualquier host, representado por `%`).
4.  Haz clic en **`Add`** (Agregar).

---

### Paso 4: Creación de la Base de Datos del Negocio

1.  En la barra lateral izquierda, haz clic en la sección **`Databases`** (Bases de datos).
2.  Verás una lista de bases de datos internas del sistema. Haz clic en el botón **`Create Database`** (Crear base de datos).
3.  En el cuadro de texto, escribe el nombre de la base de datos para nuestro proyecto: **`banking_db`**.
4.  Deja el tipo de codificación (Collation) por defecto y haz clic en **`Create`** (Crear).

---

### Paso 5: Creación de Tablas (DDL) mediante Cloud SQL Studio

Para crear las tablas de nuestro sistema bancario dentro de la base de datos `banking_db` de forma rápida y visual sin instalar programas adicionales, utilizaremos la herramienta web oficial de GCP:

1.  En la barra lateral izquierda, haz clic en la herramienta **`Cloud SQL Studio`**.
2.  **Autenticación en la Base de Datos:**
    *   **Database (Base de datos):** Selecciona **`banking_db`** en el menú desplegable.
    *   **User name (Usuario):** Escribe **`myuser`**.
    *   **Password (Contraseña):** Escribe la contraseña correspondiente (ej: `mypass@123`).
    *   Haz clic en **`Authenticate`** (Autenticar).
3.  Se abrirá un editor de código SQL interactivo en la pantalla.
4.  **Carga del Esquema de Tablas (DDL):**
    *   Abre en tu repositorio local o en GitHub el archivo de definición de tablas: [cloudsql/ddl.sql](../cloudsql/ddl.sql).
    *   Copia todo el contenido de ese archivo y pégalo en la ventana del editor SQL en Cloud SQL Studio.
    *   El script creará las siguientes tablas relacionales físicas:
        *   `customers`: Almacena información KYC de clientes.
        *   `accounts`: Almacena el tipo de cuenta, divisa y saldo financiero.
        *   `transactions`: Almacena cada operación ejecutada.
5.  Haz clic en el botón **`Run`** (Ejecutar) en la barra superior del editor.
6.  En la consola inferior verás el mensaje indicando que las sentencias se ejecutaron correctamente y, a la izquierda, en el menú jerárquico, aparecerán las tablas creadas.

---

### Paso 6: Ingesta del Lote Inicial de Datos (Sample Data)

1.  Borra el contenido del editor SQL en Cloud SQL Studio.
2.  Abre el archivo correspondiente al primer lote de datos operacionales de prueba en tu repositorio local: [cloudsql/1st_batch_data.sql](../cloudsql/1st_batch_data.sql).
3.  Copia todas las sentencias `INSERT INTO` contenidas en ese archivo y pégalas en el editor web.
4.  Haz clic en el botón **`Run`** (Ejecutar). Las sentencias insertarán registros de clientes, cuentas y transacciones bancarias iniciales en tus tablas.
5.  **Verificación Final:**
    *   Abre una nueva pestaña de consulta en el editor y escribe la siguiente consulta de prueba:
        ```sql
        SELECT * FROM customers LIMIT 5;
        ```
    *   Haz clic en **`Run`** y confirma que la base de datos retorna los registros de clientes cargados correctamente en la tabla de resultados inferior.

## 7. Configuración del Origen 2 - Pub/Sub (Set Up Source 2 - Pub/Sub)

Esta sección describe de manera detallada y sencilla cómo configurar **Google Cloud Pub/Sub** para capturar eventos transaccionales en tiempo real. Pub/Sub funciona como un servicio de mensajería distribuido e intermediario (*middleware*) desacoplado, donde las aplicaciones (productores) envían datos a un canal llamado **Tema (Topic)** y los consumidores (suscriptores) leen los datos a través de una **Suscripción (Subscription)**.

En este módulo, crearemos un flujo de transacciones bancarias en tiempo real utilizando un emulador en Python que enviará transacciones simuladas (compras con tarjeta, transferencias por aplicación, cajeros automáticos, etc.) a nuestro sistema de mensajería.

---

### Paso 1: Acceso a Pub/Sub en la Consola de GCP

1.  Abre tu navegador de internet e ingresa a la consola de Google Cloud: [console.cloud.google.com](https://console.cloud.google.com).
2.  Inicia sesión y asegúrate de tener seleccionado tu proyecto activo: **`Dev Banking 2026`** en la barra superior.
3.  En la barra de búsqueda de la consola, escribe **`Pub/Sub`** y selecciona el primer resultado.
4.  Se abrirá el panel principal de Pub/Sub.

---

### Paso 2: Creación del Tema Principal (Topic)

1.  En la barra lateral izquierda de Pub/Sub, haz clic en **`Topics`** (Temas).
2.  Haz clic en el botón **`Create Topic`** (Crear tema) en la parte superior.
3.  En el formulario de creación:
    *   **Topic ID (ID del tema):** Escribe el nombre exacto de nuestro canal de transacciones principales: **`banking-transactions-topic`**.
    *   **Configuración por defecto:** Desmarca la casilla *`Use a default subscription`* (Usar una suscripción predeterminada) si está seleccionada. Crearemos la suscripción de forma personalizada en los siguientes pasos.
4.  Haz clic en el botón **`Create`** (Crear). Ahora tu tema de transacciones operacionales está activo.

---

### Paso 3: Creación del Tema de Cola de Mensajes Fallidos (Dead Letter Topic - DLQ)

En sistemas en tiempo real de producción, cuando un mensaje tiene un formato erróneo o el sistema suscriptor falla repetidamente al procesarlo, no queremos bloquear la cola de mensajería ni perder el dato. Para ello, crearemos una cola de mensajes fallidos (*Dead Letter Queue*), donde los mensajes problemáticos se redirigen automáticamente para su posterior análisis.

1.  Vuelve al panel de **`Topics`** y haz clic de nuevo en **`Create Topic`**.
2.  En el formulario:
    *   **Topic ID (ID del tema):** Escribe el nombre exclusivo para eventos fallidos: **`banking-transactions-deadletter`**.
    *   **Configuración por defecto:** Asegúrate de desmarcar la casilla de suscripción predeterminada.
3.  Haz clic en **`Create`** (Crear).

---

### Paso 4: Creación y Configuración de la Suscripción (Subscription)

La suscripción es la entidad que conecta el Tema de Pub/Sub con los lectores de datos finales (en nuestro caso, Cloud Dataflow).

1.  En la barra lateral izquierda de Pub/Sub, haz clic en **`Subscriptions`** (Suscripciones).
2.  Haz clic en **`Create Subscription`** (Crear suscripción) en la parte superior.
3.  Llena el formulario con la siguiente información:
    *   **Subscription ID (ID de suscripción):** Escribe **`banking-transactions-sub`**.
    *   **Select a Cloud Pub/Sub topic:** Haz clic en el menú desplegable y selecciona el tema principal que creaste anteriormente: **`projects/Dev-Banking-2026/topics/banking-transactions-topic`** (el ID del proyecto puede variar según tu cuenta).
    *   **Delivery Type (Tipo de entrega):** Selecciona **`Pull`** (Tracción). Esto significa que nuestro pipeline de datos (Dataflow) solicitará activamente los mensajes de la cola a su propio ritmo, en lugar de que Pub/Sub los empuje a la fuerza (*Push*).
    *   **Message Retention (Retención de mensajes):** Deja los valores por defecto (los mensajes no confirmados se retienen en la cola hasta por un máximo de 7 días).
    *   **Acknowledgment deadline (Plazo de confirmación):** Configúralo en **`10 seconds`** (tiempo estándar que tiene el lector para confirmar que procesó el mensaje antes de que Pub/Sub intente enviarlo nuevamente).
    *   **Configuración de Mensajes Fallidos (Dead lettering):**
        *   Marca la casilla **`Enable dead lettering`** (Habilitar cola de mensajes fallidos).
        *   **Dead letter topic:** Selecciona tu tema de errores: **`projects/Dev-Banking-2026/topics/banking-transactions-deadletter`**.
        *   **Maximum delivery attempts (Intentos máximos de entrega):** Configúralo en **`5`** (si un mensaje falla 5 veces consecutivas al ser procesado, se enviará automáticamente a la cola de fallidos).
4.  Haz clic en el botón **`Create`** (Crear) al final de la página.

---

### Paso 5: Ejecución del Simulador de Transacciones Bancarias (Python Producer)

Para verificar que nuestro sistema Pub/Sub funciona, utilizaremos la terminal interactiva **GCP Cloud Shell** para ejecutar un script en Python que simula transacciones financieras reales (monto, cliente, canal, comercio y estado).

1.  Activa Cloud Shell haciendo clic en el botón **`Activate Cloud Shell`** (ícono `>_` en la esquina superior derecha de la consola de GCP).
2.  **Instalación del Cliente de Pub/Sub en Python:**
    En la consola de Cloud Shell, ejecuta el siguiente comando para instalar la librería oficial de Pub/Sub necesaria para el script de Python:
    ```bash
    pip install google-cloud-pubsub
    ```
3.  **Ejecución del Script del Repositorio:**
    *   El código simulador ya está escrito en tu repositorio local en la ruta: [pubsub/banking_transaction_producer.py](../pubsub/banking_transaction_producer.py).
    *   Para ejecutar el generador de eventos, corre el siguiente comando en la terminal de Cloud Shell (reemplaza `TU_PROJECT_ID` con el ID de tu proyecto en GCP, ej. `dev-banking-2026`):
    ```bash
    python pubsub/banking_transaction_producer.py \
      --project-id TU_PROJECT_ID \
      --topic-id banking-transactions-topic \
      --events-per-second 2 \
      --max-events 100
    ```
    *   *Nota:* Este comando generará 2 transacciones ficticias por segundo y se detendrá al llegar a 100 eventos creados. Verás impreso en la terminal cada transacción generada de forma dinámica.

---

## 8. Configuración de la Capa de Aterrizaje / Landing Layer (Set Up the Landing Layer)

Esta sección describe cómo configurar la **Capa de Aterrizaje (Landing Layer / Staging Area)** utilizando **Google Cloud Storage (GCS)**. 

Google Cloud Storage es un servicio administrado de almacenamiento basado en objetos, altamente escalable, seguro y redundante. En él guardaremos los archivos temporales y los datos crudos en formato Parquet procedentes de nuestras fuentes antes de cargarlos en BigQuery.

Para organizar los datos de manera estructurada y segura, crearemos dos contenedores lógicos llamados **Buckets** (cubos de almacenamiento):
1.  **Bucket Raw (Capa de Aterrizaje de Datos Crudos):** Almacenará los datos que Dataflow ingesta desde Cloud SQL y Pub/Sub.
2.  **Bucket Temporal (Temp):** Se utilizará para el procesamiento intermedio de los pipelines de Apache Beam y Spark.

> [!NOTE]
> Los nombres de los Buckets en Google Cloud Storage son globales. Esto significa que ningún otro usuario en el mundo de GCP puede tener un bucket con el mismo nombre. Por lo tanto, añadiremos el ID único de tu proyecto al final del nombre de cada bucket.

---

### Paso 1: Acceso a Cloud Storage en la Consola de GCP

1.  Abre tu navegador de internet e ingresa a la consola de Google Cloud: [console.cloud.google.com](https://console.cloud.google.com).
2.  Inicia sesión y asegúrate de seleccionar tu proyecto activo: **`Dev Banking 2026`** en la barra superior.
3.  En la barra de búsqueda de la consola, escribe **`Cloud Storage`** y selecciona el primer resultado.
4.  Se abrirá el panel principal de Cloud Storage.

---

### Paso 2: Creación del Bucket de Datos Crudos (Capa Landing / Raw)

1.  Haz clic en el botón **`Create`** (Crear cubo / Create Bucket) en la parte superior del panel.
2.  **Nombre del Bucket (Name your bucket):**
    *   Ingresa un nombre descriptivo único a nivel global. Te recomendamos utilizar el formato: **`banking-raw-dev-<ID_DE_TU_PROYECTO>`** (reemplaza `<ID_DE_TU_PROYECTO>` con el ID único de tu proyecto de GCP).
    *   Haz clic en **`Continue`** (Continuar).
3.  **Ubicación del Dato (Choose where to store your data):**
    *   **Location type:** Selecciona **`Multi-region`** (para redundancia en múltiples áreas geográficas) o **`Region`** (Zona única) según tus requerimientos. Para fines de este laboratorio y optimización de latencia en laboratorios, puedes elegir **`Multi-region`** (ej: `US`).
    *   Haz clic en **`Continue`**.
4.  **Clase de Almacenamiento (Choose a storage class for your data):**
    *   Selecciona la clase **`Standard`** (Almacenamiento estándar). Esta clase es la adecuada para datos que se acceden con alta frecuencia y de forma continua para análisis diarios.
    *   Haz clic en **`Continue`**.
5.  **Control de Acceso (Choose how to control access to objects):**
    *   Desmarca la opción *`Enforce public access prevention on this bucket`* (Prevenir acceso público) solo si vas a requerir enlaces directos públicos sin tokens, pero para seguridad del banco la dejamos **marcada**.
    *   **Access control:** Selecciona **`Fine-grained`** (Detallado / ACLs). Esta opción permite aplicar permisos individuales y específicos por objeto dentro del bucket, ideal para estructurar datos de diferentes fuentes.
    *   Haz clic en **`Continue`**.
6.  **Protección de Datos (Choose how to protect object data):**
    *   Asegúrate de tener seleccionada la opción **`Soft delete policy`** (Política de eliminación suave / recuperación de datos eliminados) si deseas conservar archivos eliminados temporalmente, o puedes desactivarla para el laboratorio si quieres evitar costos de retención por datos que borres y re-escribas.
    *   Haz clic en el botón **`Create`** (Crear).
7.  Si aparece un cuadro de advertencia sobre la prevención de acceso público, confírmalo haciendo clic en **`Confirm`**.

---

### Paso 3: Organización de Carpetas dentro del Bucket Raw

Para que nuestras tuberías de ingesta (Pipelines) guarden los archivos Parquet de manera organizada por entidad de negocio, crearemos una estructura de carpetas físicas dentro de nuestro nuevo Bucket `banking-raw-dev-<ID_DE_TU_PROYECTO>`:

1.  Dentro del bucket recién creado, haz clic en el botón **`Create Folder`** (Crear carpeta) en el panel central.
2.  Ingresa el nombre en minúsculas: **`customers`** (para guardar los datos crudos de clientes). Haz clic en **`Create`**.
3.  Vuelve a hacer clic en **`Create Folder`**, ingresa el nombre: **`accounts`** (para las cuentas bancarias) y haz clic en **`Create`**.
4.  Haz clic por última vez en **`Create Folder`**, ingresa el nombre: **`transactions`** (para almacenar los archivos de transacciones históricas y en streaming). Haz clic en **`Create`**.

*Ahora tu bucket tiene una estructura organizada de carpetas:*
```text
banking-raw-dev-<ID_DE_TU_PROYECTO>/
├── accounts/
├── customers/
└── transactions/
```

---

### Paso 4: Creación del Bucket Temporal (Temp)

Este bucket se utilizará para almacenar los logs temporales, archivos de configuración de Apache Spark y caché intermedio generado durante la ejecución de los pipelines.

1.  Vuelve al panel principal de **`Cloud Storage`** haciendo clic en "Buckets" en la barra lateral izquierda.
2.  Haz clic de nuevo en el botón **`Create`** (Crear cubo).
3.  **Nombre del Bucket:**
    *   Escribe el nombre único global con el formato: **`banking-temp-dev-<ID_DE_TU_PROYECTO>`**.
    *   Haz clic en **`Continue`**.
4.  **Ubicación del Dato:** Selecciona la misma región/ubicación que elegiste para el bucket Raw (ej: Multi-region `US`) y haz clic en **`Continue`**.
5.  **Clase de Almacenamiento:** Selecciona **`Standard`** y haz clic en **`Continue`**.
6.  **Control de Acceso:** Selecciona **`Fine-grained`** (Detallado) y haz clic en **`Continue`**.
7.  Haz clic en **`Create`** (Crear) y confirma la alerta de acceso si se te solicita.

## 9. Configuración de la Capa de Metadatos / Metadata Layer (Set Up the Metadata Layer)

Esta sección explica de manera detallada y paso a paso cómo crear la **Capa de Metadatos (Metadata Layer)** en **Google BigQuery**. 

### ¿Por qué una arquitectura guiada por Metadatos (Metadata-Driven)?

En lugar de realizar cargas completas (*Full Loads*) de las tablas (que borran todo el contenido y vuelven a cargar millones de registros, consumiendo gran cantidad de tiempo y recursos computacionales costosos), nuestro pipeline utiliza **Captura de Datos Cambiados (CDC)**. De este modo, solo se cargan los registros creados o modificados recientemente (los datos delta).

Para automatizar esto sin escribir código rígido, creamos un **marco guiado por metadatos**:
*   Utilizamos una tabla central que guarda el estado de cada tabla de origen, indicando si está activa en la ingesta y cuándo fue la última vez que se leyó con éxito.
*   Los pipelines leen esta configuración dinámicamente. Esto nos permite desactivar ingestas de tablas o cambiar el ritmo de carga con solo actualizar una celda de base de datos en BigQuery, sin alterar una sola línea del código de Dataflow.

---

### Paso 1: Acceso a BigQuery en la Consola de GCP

1.  Abre tu navegador de internet e ingresa a la consola de Google Cloud: [console.cloud.google.com](https://console.cloud.google.com).
2.  Inicia sesión y asegúrate de seleccionar tu proyecto activo: **`Dev Banking 2026`** en la barra superior.
3.  En la barra de búsqueda de la consola, escribe **`BigQuery`** y selecciona el primer resultado.

### Paso 3: Creación y Población de la Tabla de Configuración CDC (`cdc_config`)

Esta tabla es el corazón de la ingesta incremental. Controla qué tablas se ingestan y la marca de tiempo de la última carga exitosa.

1.  Borra el contenido del editor SQL en BigQuery.
2.  Copia y ejecuta la DDL del archivo: [cdc_config.sql](../airflow/data/bigquery/table_ddl/banking_metadata/cdc_config.sql):
    ```sql
    CREATE OR REPLACE TABLE `banking_metadata.cdc_config` (
      source STRING,
      table_name STRING,
      primary_key STRING,
      watermark_column STRING,
      is_active BOOL,
      last_success_ts TIMESTAMP
    );

    INSERT INTO `banking_metadata.cdc_config` VALUES
    ('cloudsql', 'customers', 'customer_id', 'updated_at', TRUE, '1970-01-01'),
    ('cloudsql', 'accounts', 'account_id', 'updated_at', TRUE, '1970-01-01'),
    ('cloudsql', 'transactions', 'transaction_id', 'updated_at', TRUE, '1970-01-01');
    ```
3.  Haz clic en **`Run`**.
4.  **Explicación de Columnas Clave:**
    *   `is_active`: Indica si el pipeline de Dataflow debe procesar la tabla (`TRUE`) o ignorarla (`FALSE`).
    *   `last_success_ts`: Registra la marca de tiempo del último registro procesado con éxito. Está inicializado en `1970-01-01` (marca de tiempo Unix por defecto) para forzar al pipeline a que realice una carga histórica completa en su primera ejecución. Posteriormente, el pipeline de Dataflow actualizará dinámicamente este campo al terminar la ejecución.
